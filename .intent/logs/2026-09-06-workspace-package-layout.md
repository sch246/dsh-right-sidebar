# Workspace package layout

The user requests independent repositories with a common root-workspace and `packages/` organization. This realization places the sidebar package in `packages/dsh-right-sidebar/`; the repository root owns development dependencies, the pnpm workspace and operation scripts. Package name `@dsh-external/dsh-right-sidebar`, version `0.0.1`, exports, loader registration, view ids and persisted formats remain unchanged. Protocol 0.2 and empty active/candidate lock selections remain unchanged; historical locks are frozen.

The package owns `src/`, `tests/`, compiler and bundler configs, its manifest, `cordis.patch.yml`, `patches/`, package README, license copy and generated `lib/`. The root does not retain plugin exports or source/artifact forwarding paths. Build/setup/uninstall remain root commands; setup registers the absolute child package path and uninstall resolves the same package name from that package directory. Host patch application, receipts, generation and rebuilding retain their existing lifecycle; this work does not execute those operations.

## Storage identity

`packages/dsh-right-sidebar/src/client/service.ts` fixes `STORAGE_KEY` to `@dsh-external/dsh-right-sidebar/workbench/1` and `INVALID_STORAGE_KEY` to `@dsh-external/dsh-right-sidebar/workbench/1-invalid-backup`. These literals contain the package name, but neither package location nor checkout path is an input. `readPersisted()` and `writePersisted()` use those keys directly; session indexing uses `String(sessionId)`. Persistence projects instance id, viewId and feature-owned restoreDescriptor without re-namespacing. All runtime source files and the Host patch retain their bytes. The Host patch still persists `detailsBySession` under `dsh.layout.panels.v2`. With package name, renderer ids, origin and stored data retained, directory relocation does not require layout or draft migration.

## Consumer cutover

Existing profile links to the checkout root require a `dsh plugin add /absolute/plugin-checkout/packages/dsh-right-sidebar` transaction, with resolution, lockfile, Bundle and boot checks before managed activation. File-viewer, file-manager and resource-links declare root-relative sidebar links and must update those in their own repositories, together with any direct source aliases or build links. Direct readers of root `src/`, `lib/`, `cordis.patch.yml` or `patches/` must use the child path. Root script paths remain valid. No other repository, live profile, service or browser storage is modified here.
